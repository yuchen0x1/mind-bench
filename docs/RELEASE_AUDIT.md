# 0.2.0 发布审计

日期：2026-11-13。对象为项目源码、Git 历史、Vite 前端产物及完整应用发布包。该审计不等于渗透测试或安全认证。

## 1. 总览

前端静态扫描检查 4 个文件，未检出扫描器覆盖的 source map、明文凭证、调试产物或本机路径暴露。扫描器给出 100/A，仅表示这些静态规则未命中，不能解释为无法逆向；本项目本就以 MIT 公开源码。

本地已通过 52 项单元/API、8 项 Chromium E2E、构建与独立发布包启动检查。4 个历史提交、79 个独立 Git blob 的凭证模式与私有数据路径扫描未命中；该模式扫描不能保证不存在所有种类的秘密。

| 编号 | 严重度 | 发现与影响 | 处理 |

## 3. 逐项证据与修复

- `scripts/package-release.mjs` 只复制显式文件清单，不包含 `data/`、`.env`、`.key`、依赖目录、Git 和本地开发记录。`release-manifest.json` 覆盖逐文件 SHA-256，下载包另有 `SHA256SUMS.txt`。
- `scripts/verify-release.mjs` 在系统临时目录解压并核对文件摘要，仅安装生产依赖，启动包内服务，检查版本、页面资源、题库与空白用户数据，然后清理临时目录。
- `src/server.mjs` 的本机接口来源检查、设置校验、导入逐行检查、DISTINCT 计数与运行版本筛选由 `tests/release-audit.test.js` 验证。
- `src/scoring.mjs` 对异常评分规则返回未评分，保留原文；显式客观题空回答计 0 分，人工题仍为未评分。
- `src/providers.mjs` 按供应商使用默认端点，规范 Anthropic/Gemini/Ollama 路径，并检查 Base URL 协议与本机地址。它不构成远程多用户服务的 SSRF 允许列表。
- Git 历史未包含数据库、`.key` 或 `.env`。本地开发记录已从当前索引移除并加入忽略规则，历史仍保留原提交，未重写历史。
- 本地 `npm audit`：镜像源不支持审计端点，官方端点连接重置，结果为 **BLOCKED**。CI 使用官方端点检查生产依赖，并以 high 级别作为门禁；最终远程结果以 Actions 为准。

## 4. 客户端无法解决的问题

源码公开意味着前端算法和接口结构可被阅读，这是许可证允许的行为。混淆不会替代密钥隔离。项目只把用户凭证保存在本机后端，不将其编译进前端；但获得数据库与本机密钥的人仍可解密。

本项目没有公网认证、多租户授权或代码执行沙箱。保持回环监听；如果改为共享服务，需另行设计身份认证、数据隔离和供应商地址访问控制。浏览器刷新提示不是安装器更新；SHA-256 校验文件不是独立数字签名。

## 5. 修复顺序与发布边界

P0：阻止用户数据库和密钥进入发布包、错误 Key 脱敏。P1：修复本机来源检查、完整打包和评分数据可靠性。P2：固定 CI Actions、双系统验证、依赖维护、文档与截图。

这些本地修复与回归已完成。远程 CI、公开仓库权限和 Release 下载校验需在推送后确认；真实供应商计费调用、Docker 本轮复测及公网部署不在本次通过项内。
