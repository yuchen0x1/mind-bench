# MIND BENCH 基准方法论

## 目标与范围

MIND BENCH 面向大语言模型的**工程评测、回归与横向比较**。它不测量人的智商，不是临床、教育或心理测量工具。`MIND BENCH SCORE` 是本平台自定义的 0—1000 运行汇总指标，**不可解释为 IQ**。

它适合回答的问题：

- 同一模型在提示词/参数变更后是否退化？
- 多个候选模型在我关心的能力维度上表现差异有多大？
- 某次供应商升级后，历史分数是否出现异常波动？

它**不适合**回答的问题：

- 某模型"有多聪明"（无统一定义，且强依赖题目集）
- 某模型是否适合某具体生产任务（需任务内评测）
- 跨平台分数对比（题目集、评分规则均不同）

## 题目来源分类

每条题目必须标注来源类型，来源类型决定它能否被公开再分发：

| 标签 | 含义 | 再分发 |
|---|---|---|
| `A` original | MIND BENCH 自主编写 | 可（本项目原创内容） |
| `B` community | 开源社区题目 | 按原仓库许可证，需逐题核实 |
| `C` self-designed | 为本平台定制的题型 | 可 |
| `D` ai_verified | AI 辅助生成 + 人工逐题验证 | 需人工验证记录 |
| `E` user | 用户自建/导入 | 由导入者确认 |

**当前状态**：203 题全部为 `A`（原创），来自 `source-original-v1`。这避免了任何许可证风险，但也意味着题目代表性尚未经过外部校验——这是明确标注的局限。

**未验证的题不得使用 `D` 标签。** 只有完成逐题人工复核并留有记录，才能从 `review_required` 迁移到 `verified`。

## 评分方法

### 确定性客观规则

支持 `exact`、`one_of`、`contains`、`all_keywords`、`any_keywords`、`numeric`（含容差）、`regex`、`json`、`word_limit`、`manual`。

规则匹配**不等于**全面语义正确率。关键词命中无法识别上下文否定、语义等价与自相矛盾。因此：

- 只有能被字符串/数值客观判定的题才配置规则评分；
- `all_keywords` 类题必须在 `notes` 中说明"关键词齐备即视为通过"的判定前提；
- 数值题的容差必须写进 `scoring_rule`，不能依赖隐式四舍五入。

### AI 裁判

已实现（`src/judge.mjs`）。要求：盲化被测模型标识、rubric 固定且来自题目定义、严格 JSON Schema 校验、服务端重算总分、禁止自评、支持最多 3 位裁判交叉验证、人工复核优先、完整记录裁判模型与版本。

裁判输出被视为**主观信号**，在数据库中通过 `evaluator_type='judge'` 与规则分、人工分严格区分。报告中不会把裁判分标作"客观正确率"。

解析失败（缺维度、多维度、越界、自由文本）一律拒绝并报告，**不降级为 0 分**。

### 人工评分

开放式创造力、论证质量、科学实验设计与复杂代码问题使用人工评分（0—100）与评语，`evaluator_type='human'`。未评分结果为 `NULL`，**不按零分**参与平均值。

正式研究建议双人独立评分并报告一致性（如 Cohen's κ）；当前 UI 只支持单次人工复核。

## 聚合与排行榜

```text
单题 0—100
  → 分类均值（仅该分类下的运行）
  → 按 15 类权重加权平均（仅已覆盖分类归一化）
  → × 10
  → MIND BENCH SCORE (0—1000)
```

规则：

- **缺测分类不按 0 计**，只在已覆盖分类上加权并暴露 `category_coverage`。理由：把未测类别当 0 会系统性惩罚覆盖不全的模型，产生失真的低分。
- **权重为 0 的分类排除**出聚合。
- **准入**：每模型至少 `minimum_leaderboard_runs`（默认 10）条非 Mock、已完成、有评分的记录才进入正式榜（`qualified`）。按分类筛选时门槛同样适用。
- **不完整不混入**：失败、取消、无效、Mock、未评分的记录**不参与**聚合，也不作为 0 分加入。
- **provisional 区**：样本不足者单列展示，不占名次，并给出原因。
- **趋势**：近 7 日加权分 vs 前 7 日加权分。

榜单是**本地样本汇总**，不代表所有模型，也不提供统计置信区间。10 条门槛是产品级噪声控制，不是显著性检验。

## 可复现性清单

每个 run 持久化以下字段：

- 题目 ID 与题目版本
- 模型 ID 与用户在 `model_version` 中登记的声明版本
- 供应商类型与 Base URL
- 实际发送的提示词（含当次覆盖）
- 温度、max_tokens、超时、重试
- 调用时间戳、耗时、输入/输出 Token
- 费用配置（单价）与估算费用
- **原始回答全文**
- 评分器类型（`rule` / `judge` / `human`）、具体规则或裁判模型与版本
- 评分理由 / 裁判逐维度理由

外部 API 可能静默升级，因此使用者应主动登记实际模型版本，并保留供应商与日期信息。

随机模式记录实际抽到的题目 ID 列表；稳定性模式记录同一题的重复 run（`repeats`），便于计算输出一致性。

排行榜导出的 JSON 额外包含 `weights` 与 `threshold` 快照——没有这两项，跨时间的分数比较缺乏依据。

## 质量控制

初始内置题目是**自主设计草稿**，尽量以独立题型构成，但仍需领域专家逐题复核以下方面：

1. 题干是否充分（无歧义、无信息缺失）
2. 标准答案是否唯一（或已明确枚举可接受答案）
3. 是否存在语义等价但被规则误判的表述
4. 数值容差是否合理
5. 关键词规则是否存在否定语境误判风险
6. 难度标注是否与实际认知负荷相符

复核状态通过 `verification_status` 表达：`draft`（草案）→ `review_required`（待复核）→ `verified`（已验证）。用户可通过工作台或 API 更新状态。

**禁止把题目数量当作质量代理。** 203 道未经专家复核的题，其证据强度不高于 30 道经过双人复核的题。

## 与其他基准的关系

MIND BENCH 在方法论上参考了 lm-evaluation-harness（任务配置与 few-shot 组织）、HELM（多维度场景化评测）、lighteval（轻量适配器）、promptfoo（提示词回归测试）、OpenAI Evals（YAML 评测定义）、BIG-bench（题目多样性）与 ARC-AGI（抽象推理任务设计）。**未复制**任何需授权的题目数据。详细对照见 [开源项目研究](OPEN_SOURCE_RESEARCH.md)。
