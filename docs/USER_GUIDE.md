# MIND BENCH 用户指南

## 启动

要求 Node.js 22.5+（建议 Node 24）。

```bash
npm ci
npm run build
npm start
```

打开 <http://127.0.0.1:3000>。Windows 在项目根目录用 PowerShell / Windows Terminal 执行同样的 npm 命令即可。Docker 用法见 [README](../README.md#docker)。

开发模式需两个终端分别运行 `npm run server` 与 `npm run dev`；Vite 开发服务未配置 `/api` 代理，日常使用与端到端测试都走生产构建。

## 一、添加模型

1. 进入「模型管理」→「添加供应商」。
2. 选择类型（如 `DeepSeek`、`Ollama`、`openai-compatible`），填写名称、Base URL、API Key。
   - Key 只在本机提交，后端 AES-256-GCM 加密后写入 SQLite，之后任何接口都不返回明文。
3. 保存后点「测试连接」，确认凭证有效。
4. 点「获取模型列表」——平台会调用供应商的模型发现端点，从下拉中勾选要添加的模型。
   - OpenAI 兼容走 `/models`；Ollama 走 `/api/tags`；Gemini 走 `/v1beta/models`。
   - 若供应商不支持，可手填 model ID。
5. 设置显示名、温度、最大 Token、超时、重试次数、输入/输出单价。
6. 可勾选「设为默认模型」。

> **Mock 沙盒**：无需 Key，用于验证全流程。报告有显式 `MOCK` 标签，**不计分、不入榜、不作为 AI 裁判候选**。

> Ollama / LM Studio 需先启动本地服务并开启兼容 API。默认地址分别为 `http://127.0.0.1:11434` 与 `http://127.0.0.1:1234/v1`。

## 二、题库探索

- 顶部搜索框支持按标题与提示词模糊匹配。
- 左侧分类树点击即筛选；支持难度筛选与来源筛选。
- 右上角切换**卡片视图 / 列表视图**——列表视图信息密度更高，适合快速通读。
- 卡片上的星标切换收藏；勾选框用于多选后一次性发往测试中心。

---

## 三、单题详情

左侧是题目信息区：

- 中文提示词、英文提示词（可切换）
- 测试目标、参考答案（默认折叠）、评分规则、评分维度、常见错误
- 来源、许可证、版本号、验证状态徽章
- **版本历史**：点「版本历史」查看所有历史快照与变更说明
- **变体**：同一考点的不同问法，可在工作台维护
- 顶部操作：复制提示词、复制为新题、编辑副本、收藏、纯文本 / Markdown 视图

右侧是模型与运行区：

- 模型多选（可「选择全部已启用模型」）
- 发送 / 停止 / 重测
- 原始回答（**原样展示，不做改写**）
- 耗时、Token、费用、HTTP 状态
- 「粘贴外部回答」：把别的渠道得到的回答录入进来评分，不消耗 Token。该运行会标记为“外部回答”，可进入报告与统一评分，但不会冒充所选模型或进入正式排行榜。

> **关于思维链**：平台不请求也不展示隐藏推理链。只显示供应商响应中明确返回的文本，不推测、不补写。

**复制为新题**会真实创建一条新记录（`derived_from` 指向原题），随后自动跳到提示词工作台继续编辑——不是复制到剪贴板了事。

## 四、测试中心（8 种模式）

| 模式 | 说明 |
|---|---|
| 单题挑战 | 选择一题并对比多个模型 |
| 分类挑战 | 抽取单个能力分类下的多道题 |
| 综合评测 | 跨分类采样，构建能力快照 |
| 极限挑战 | 优先运行高难度与专家级题目 |
| 随机挑战 | 每次随机生成不同题目组合 |
| 稳定性测试 | 重复相同题目，衡量输出一致性 |
| 自定义测试 | 自行配置分类、题量、难度、模型 |
| 外部回答评分 | 输入已有回答后进行人工评分 |

配置项：题量、难度、重复次数、模型集合。并发默认 4，可通过 `MIND_BENCH_CONCURRENCY` 调整（上限 8）。

运行中可点「取消」中断剩余任务。已完成的运行结果**不会丢失**。

## 五、测试报告

### KPI 区

5 个指标：完成数、平均分、总耗时、总 Token、AI 裁判覆盖率。

### 「回答与评分」`Tab`

逐条展示：题目、模型、原始回答、评分、评分理由、耗时、Token、费用。

- 可对每条手动评分（0—100）并写评语，标记后即成为 `human` 评分。
- 点「AI 裁判」为该条发起裁判，选择裁判模型（不能是被测模型本身）。

### 「并排对比」`Tab`

- 同题多模型并排卡片
- **LCS 逐词差异高亮**：绿色为共同片段，高亮为各模型独有内容
- 逐项评分矩阵：横向对比各维度得分

### AI 裁判面板

- 可选最多 3 位裁判，点「批量裁判」一次评完整个会话
- 显示每位裁判的逐维度分数与理由
- 多名裁判时显示**均值 / 极差 / 一致度**；极差 ≥ 25 时提示「裁判分歧较大」
- 裁判模型名与版本一并记录
- 无效裁判（JSON 不合规）会单独列出并说明原因，**不会写成 0 分**

### 导出

右上角可导出本次会话为 JSON 或 CSV，包含原始回答与评分依据。

## 六、提示词工作台

三栏布局：

- **左栏**：自建题目与副本列表，显示变体数量
- **中栏**：编辑器——标题、分类、子分类、难度、中英文提示词、测试目标、参考答案、评分规则（可视化选择 10 种方法）、评分维度、常见错误、备注、是否公开
- **右栏**：实时评分预览（用当前规则给一段示例回答打分）+ 变体管理（新建 / 删除）

从内置题「编辑副本」进入时，原题字段会预填，保存即生成独立题目，不修改原题。

---

## 七、排行榜

- 顶部切换：综合榜 / 15 个分类榜
- 版本下拉：按题库版本过滤，避免跨版本混排
- 每行显示：排名、模型、供应商、MIND BENCH SCORE（0—1000）、覆盖度、测试数、平均耗时、最近时间、趋势
- 点击行展开：15 类分项得分条形图
- `provisional` 区：样本不足的模型单列，**不占名次**，可点击进入模型档案
- 右侧导出按钮：CSV / JSON（导出文件内含权重与阈值快照）

> 榜单上的分数是 **MIND BENCH SCORE**，不是 IQ，也不代表通用智能。

---

## 八、模型档案

从排行榜或模型管理点「详情」进入：

- 顶部：模型名、供应商、参数、成本、默认标记
- 能力雷达图：15 个维度
- 得分走势面积图：按时间聚合
- 统计：运行数、成功率、平均分、平均耗时
- 最近运行表：点击直达对应报告
- 已裁判运行数

## 九、题库导入

两条路径：

### 1. 原生 JSON 导入

下载示例 JSON 后按格式填写。最低字段：`title`、`categoryId`、`promptZh`。建议完整提供来源名称、网址、许可证、子分类、难度、参考答案、评分规则、测试目标、版本与验证状态。

### 2. 外部数据集适配

选择 JSONL 或 CSV 文件，填写：

- **许可证（必填）**——不填无法导入，这是硬性要求
- 可选字段映射（如 `question`→`promptZh`、`answer`→`referenceAnswer`）

导入结果会显示：成功数、跳过数、逐条错误（含行号）、警告。单批最多 1000 条。导入题的验证状态为 `imported`。

> 导入前请自行确认数据集的再分发权与署名要求。**不要**把不可再分发的数据提交到公开仓库。

## 十、系统设置

| 设置项 | 键 | 说明 |
|---|---|---|
| 分类权重 | `score_weights` | 15 个类别的权重，**直接参与排行榜加权计算** |
| 最小样本数 | `minimum_leaderboard_runs` | 进入正式榜所需的最小有效样本，默认 10 |
| 默认模型 | `default_model_id` | 新建测试时的预选模型 |

修改权重后，排行榜会立即按新权重重算（页面刷新即可看到）。报告页会说明当前是否使用了非等权配置。

## 常见问题

**Q：为什么排行榜是空的？**
A：因为还没有满足准入条件的真实运行。需要：真实供应商（非 Mock）、运行成功、有评分、且样本数达到阈值。这是设计意图——宁可空着，也不放示例数据。

**Q：为什么某条运行没有分数？**
A：三种可能：① 该题评分为 `manual` 且尚未人工/裁判评分；② AI 裁判输出不合规被拒绝；③ Mock 运行。报告页会给出具体原因。

**Q：AI 裁判把我的手动评分覆盖了吗？**
A：不会。人工评分标记 `reviewed` 后，AI 裁判跳过该条，除非显式强制。

**Q：能直接跑模型生成的代码吗？**
A：不能。本平台没有代码沙箱，编程题只评估文本答案。

**Q：换电脑怎么迁移？**
A：停止服务后，同时复制 `data/mind-bench.sqlite` 与 `data/.key` 到新机器的 `data/` 目录。只复制数据库会因缺密钥导致 API Key 无法解密。

**Q：切换主题？**
A：右上角太阳/月亮图标，选择保存在 localStorage。
