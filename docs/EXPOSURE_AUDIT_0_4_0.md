# v0.4.0 发布前暴露面审计

## 一、总览

目标：本项目 `dist/` Web 构建；2026-11-18 使用 `exposure_scan.py dist --profile web` 静态扫描。结果为 5 个文件、1 个 JS 产物，扫描器给出 100/100（A），未发现其规则内的静态暴露项。此分数只衡量扫描器规则，不能证明整体应用安全。本项目采用 MIT 开源许可证，发行包按设计包含服务端源码，因此不以代码保密作为安全边界。

## 二、发现清单

| 严重度 | 发现 | 证据 |
| --- | --- | --- |
| 高 | 无已确认扫描命中 | `dist/` 内无 `.map` 与 `.env*` 文件；扫描器未报 critical/high/medium/low 项 |
| 已知产品边界 | 公网访问与多租户尚不安全 | `src/server.mjs` 本机服务无账户体系；参见 `SECURITY.md` |

## 三、证据与处理

- Web 构建没有发布 source map；Vite 默认构建未开启 `build.sourcemap`。前端 JS 仍可阅读和分析，这是公开 Web 应用的正常性质。
- 供应商 API Key 在本机服务端加密存储，接口不返回明文；浏览器产物不应含真实用户凭证。发布包校验脚本确认不携带用户数据库与密钥文件。
- `dist/` 扫描不覆盖运行时 HTTP 安全、依赖漏洞、真实用户凭证或部署配置；这些使用 API 测试、`npm audit` 与发布检查分别验证。

## 四、客户端无法解决的问题

任何放进浏览器 JS 的长期密钥、授权决策或私有模型参数都会被取得。当前设计把用户供应商凭证保存在本机服务端，浏览器只调用同源 API。若未来改成公网多用户产品，必须先建立身份认证、租户隔离、服务端授权和出站请求策略；压缩或混淆 JS 无法替代这些措施。

## 五、修复顺序

1. 当前无扫描器确认的严重/高危构建暴露项。
2. 公网部署前优先完成认证、租户隔离与 SSRF 边界；在此之前继续保持可信本机范围。
3. 持续在每次 Release 前检查构建产物、密钥排除和依赖审计；不要把静态分数作为自动发布的唯一门禁。
